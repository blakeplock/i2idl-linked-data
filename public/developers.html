Model Context Protocol

Give an assistant a reliable reference.

MCP clients supporting remote Streamable HTTP can discover and invoke the glossary's tools. The endpoint is POST-only; opening it in a browser returns HTTP 405 by design.

Connection

Add a remote MCP server in your AI client's settings, select Streamable HTTP, and use no authentication.

https://id.i2idl.org/mcp
  1. Register the URL as a remote Streamable HTTP MCP server.
  2. Discover the four read-only tools.
  3. Try get_context for learning-engineering.
  4. Preserve citations and canonical identifiers when generating an answer.
MCP Quick Start ↗AI Integration Guide ↗

Tools available

Each tool retrieves only published reference material and declares itself read-only.

  • search_conceptsFind published terms and canonical IDs.
  • get_conceptRetrieve a concept, definition, and metadata.
  • get_relationshipsRetrieve asserted broader, narrower, and related concepts.
  • get_contextRetrieve a bounded semantic context bundle with provenance.
Verified with ChatGPT and MCP Inspector. Other client support depends on transport and protocol compatibility.
EXAMPLE / TOOL ARGUMENTS
{"name":"get_context","arguments":{"id":"learning-engineering","depth":1,"maxRelated":3}}

SPARQL

Ask questions of the RDF graph.

Query endpoint

The hosted endpoint supports bounded, read-only SELECT, ASK, CONSTRUCT, and DESCRIBE queries.

https://id.i2idl.org/sparql
Open query interface →SPARQL documentation ↗

Example query

SPARQL / SELECT
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
SELECT ?concept ?label WHERE {
  ?concept a skos:Concept ;
           skos:prefLabel ?label .
} LIMIT 10

Read operations only. Query execution is bounded by the service.

Editorial & operational boundaries

Reference data with a clear provenance trail.

I2IDL concept records identify published definitions, relationships, citations, and source evidence. AI-generated explanations should distinguish explicit graph assertions from model interpretation. The public MCP service is unauthenticated and read-only; request bounds, upstream timeouts, and edge rate limiting protect service availability.
